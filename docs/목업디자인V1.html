1진행 방식 · 결과 확인 위치

Jonnathan(수석 디자이너)이 UX Flow Map · S1~S13 와이어프레임(13×6 상태 매트릭스 전 칸) · 카탈로그 2종 스펙 · 목업 제작 가이드를 설계하고, 빌더 4명이 그 스펙만을 기준으로 고충실도 HTML 목업을 병렬 제작했습니다. 빌더 질의 9건은 전부 리드/Jonnathan 판정을 거쳐 반영됐고(§5), Jonnathan 자가 리뷰는 57/60(잔여 감점은 전부 PM 결정 대기 항목)입니다.

Claude Design에서 보기: claude.ai/design → "Design System" 프로젝트에 16개 파일을 푸시했습니다 — Foundations(토큰 시트 1) · Screens(S1~S13, 13) · Catalogs(2). 카드 그룹은 파일의 @dsCard 마커 기준으로 자동 구성됩니다.

로컬에서 보기: 아래 각 카드의 "전체 보기" 링크(이 파일 기준 상대 경로, 원본: .agent-team/07-design/mockups/). 미리보기는 축소 렌더라 실제 크기는 링크로 여세요.

참고: 인계서가 참조한 docs/design.html(Design System 원본)이 리포에 없어, 인계서 §0.1이 동일 내용으로 보증한 텍스트 추출본(.discovery/00-plan/design-extracted-reference.txt)을 정본 참조로 사용했습니다.

#결정근거 · 판정자
W1S4는 항상 다중선택(1~6컷) — 순서 배지(filmstrip-order-badge 재사용, 우상단) + CTA 라벨 통합 카운터("n컷으로 계속") + 상한 toast. 사진 게시물은 "사진 1컷 선택"일 때만 format-choice에서 활성Jonnathan (wireframes v1.1) — 빌더 B 스펙 갭 질의로 촉발
W2Paper 표면 보조 토큰 3종 신설 제안: --paper-ink --paper-ink-secondary(#5C5C5C) --paper-divider(#E3E7E9) — WCAG AA 대비 계산 포함. opacity 합성 근사는 전면 금지로 규칙 강화. 정본 design.md 반영 필요Jonnathan (mockup-guide v1.1) — 빌더 A 토큰 갭 질의로 촉발
W3face-guard-notice는 다크 시트(surface-card + info 도트) — Paper는 "다크 앱 속 유일한 라이트 표면 = consent-sheet-light"로 한정Paul (PRD §0.2 근거)
W4S10 버튼 위계: [인스타 공유] = 주 CTA(앰버), [갤러리 저장] = 아웃라인 보조 — "화면당 주 CTA 1개"Paul (wireframe 위계 채택)
W5앰버 ≤3 계수는 의미론 그룹 단위(예: S4 다중선택 = 랭크 1그룹 + 선택 상태 1그룹 + CTA = 3그룹)Jonnathan (Design System "상태 단위 정의" 근거)
W6릴스 전환 효과(휩 팬·speed ramp 등)는 목업에서 리터럴 렌더하지 않고 타임라인·표로 정확 명기 — 오해 방지, 실렌더는 Develop 몫Paul/빌더 D
